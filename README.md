# Math Study Log

毎日の数学学習を、計算用紙の写真・学習内容・自由記述のメモで残す静的サイトです。

## 毎日の更新手順（VS Code・GitHub Desktop）

1. **日付フォルダを作る。** VS Codeでこのリポジトリを開き、例えば2026年11月3日なら `logs/2026/20261103/` を作ります。
2. **写真を保存する。** WebP形式の写真を `20261103-1.webp`、`20261103-2.webp` のように、1から順番に保存します。1枚目が一覧の代表画像になります。
3. **Markdownを作る。** 同じフォルダに `20261103.md` を作ります。フォルダ名・Markdown名・写真の日付部分は揃えてください。
4. **スニペットを挿入する。** 空のMarkdownで `mathlog` と入力し、「数学学習記録｜1分野」か「数学学習記録｜複数分野」を選びます。候補が出なければ `Control + Space` で補完候補を開いてください。
5. **カテゴリと写真を指定する。** `category: 未分類` の部分を選択し、既存の `⌘ + Option + C` でカテゴリを選びます。複数分野の場合は各項目の `images` に写真の連番を入力します。3分野以上の日は同じ形の項目を追加します。本文は1日共通のメモで、空欄でも構いません。
6. **GitHub DesktopでCommitする。** `math-study-log` を選び、追加・変更したファイルを確認します。Summaryに「11月3日の学習記録」などと入力してCommitします。新しい日付フォルダと写真も対象に含めてください。
7. **Pushする。** `main` ブランチへ反映し、`Push origin` を押します。別ブランチで作業している場合は、変更を `main` に取り込むと公開処理が始まります。
8. **公開結果を確認する。** GitHubのリポジトリの「Actions」で「Deploy Math Study Log」が成功したことを確認し、[数学学習記録](https://sakurak02.github.io/math-study-log/)を開きます。some-clouds の「Math」からも同じページに入れます。表示が古ければ再読み込みしてください。

JSON・一覧・HTMLを手作業で編集したり、some-clouds を更新したりする必要はありません。GitHub Actionsがテスト、トップページ・日別ページ・サイトマップの生成、GitHub Pagesへの公開を行います。

## 保存構造

```text
logs/
└── 2026/
    └── 20261103/
        ├── 20261103.md
        ├── 20261103-1.webp
        └── 20261103-2.webp
```

画像は `YYYYMMDD-1.webp` から始め、表示順に番号を付けます。複数枚の写真にも対応します。日付はフォルダ名から取得するので、Markdownの `date` 項目や日付見出しは不要です。

## 学習記録の書き方

1分野の日は `category` を指定すると、その日の写真がすべてそのカテゴリに入ります。

```markdown
---
category: 数学III｜極限
---
```

複数分野の日は `categories` にカテゴリと写真の連番を書きます。`未分類` も選べます。

```markdown
---
categories:
  - category: 数学III｜積分法
    images: [1, 2]
  - category: 数学B｜数列
    images: [3]
---

積分は置換積分を復習。数列は漸化式を進めた。
```

カテゴリ一覧から開くと指定した写真が表示され、通常の日別ページには全写真が表示されます。どのカテゴリにも指定しなかった写真は日別ページに表示されます。見つからない番号は警告してスキップします。複数のカテゴリに同じ写真を指定すると、警告を出して最初の指定を使います。

教材などの学習内容は、どちらの形式でも任意で追加できます。

```markdown
---
category: 数学III｜極限
教材: 青チャート 数学III
範囲: 数列の極限・例題15〜20
問題数: 12
用紙: 8
苦戦度: 🌧️🌧️🌧️🌧️
喜び度: ☀️☀️☀️
---

## 記録メモ

今日は計算が長かった。でも最後の問題が解けた。
```

- `category` は既存の「教科｜章」から選びます。区切りは全角の `｜` です。未指定・空欄は「未分類」になります。
- `教材` と `範囲` は自由入力です。「範囲」はカテゴリーと独立しており、分類先を変えません。
- `問題数` と `用紙` は半角の0以上の整数を入力します。`0` は「0問」「0枚」と表示します。空欄や項目自体の省略は非表示です。内部では未指定を `undefined`、明示的な空欄を `null`、入力した0を数値 `0` として区別します。
- **用紙枚数と写真枚数は別です。** 用紙8枚を1枚の写真にまとめた場合は `用紙: 8` と記入し、写真ファイルを1枚保存します。一覧には「写真 1枚」、日別ページの学習内容には「用紙枚数 8枚」と表示します。
- `苦戦度` は 🌧️、`喜び度` は ☀️ をそれぞれ1〜5個入力します。空欄・省略も可能です。数値が不正な場合やマークが指定外の場合は、対象ファイル名と理由を表示して生成を停止します。
- `categories` の各 `images` は `[1, 2]` のように1行で書きます。教材なども1行で入力します。文字列は引用符でも囲めます（例：`教材: "青チャート # 復習"`）。行末に ` # コメント` を付けることもできます。
- 記録メモは自由なMarkdownです。空欄なら見出しごと表示しません。一覧の抜粋には「記録メモ」の見出しを含めません。
- 過去の本文だけのMarkdownや、`category` と本文だけの記録も引き続き表示します。新項目がない記録に空のラベルを追加しません。過去の記録を書き換える必要はありません。

日別ページは、日付・カテゴリー、写真、教材、範囲、問題数、用紙枚数、苦戦度、喜び度、記録メモの順で表示します。カテゴリーは従来どおり最新カードと日別ページに表示し、トップページの教科→章の一覧に利用します。カテゴリーを変更すると、次の生成で分類先も変わります。

## ローカル確認

Node.js 22以上を用意し、リポジトリのフォルダで実行します。

```sh
npm ci
npm test
npm run build
```

生成物は `public/` に出力されます。`logs/` が空でも生成できます。通常の毎日の更新では、ローカルでの実行は必須ではありません。Push後にGitHub Actionsが同じテスト・生成を実行します。

## 公開ページ

- `/`：最新の写真グリッド、年月別アーカイブ、教科→章のカテゴリー別テキスト一覧
- `/daily/YYYYMMDD/`：その日の全写真、学習内容、記録メモ

公開設定は `.github/workflows/deploy.yml` で管理します。公開URL・日付フォルダ・写真の命名規則・標準カテゴリーは従来どおりです。
