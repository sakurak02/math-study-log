# Math Study Log

## 公開LOG画像の命名ルール

保存先は `content/records/YYYYMMDD/NNN/images/` です。

```text
YYYYMMDD-NNNf-M.jpg
YYYYMMDD-NNNr-M.jpg
```

- `YYYYMMDD`: 学習日。`records/` 直下の日付フォルダと一致させます。
- `NNN`: その日の学習セット番号（`001`, `002`, `003`, …）。親フォルダと一致させます。
- `f`: first（最初の答案）。`r`: retry（公開に採用した1回分の再挑戦答案）。
- `M`: その答案の画像ページ番号。1から始まる整数で、先頭に0を付けません。画像が1枚でも必ず `-1` を付けます。
- 種別と拡張子は小文字の `f` / `r` と `.jpg` を使用します。

例（同一セット内ではfirst→retry、同じ種別ではページ番号の数値順に掲載）:

```text
content/records/20260828/001/images/
  20260828-001f-1.jpg
  20260828-001f-2.jpg
  20260828-001r-1.jpg
  20260828-001r-2.jpg
```

末尾の `-1`, `-2`, `-3` は**リトライ回数ではありません**。
ローカルで何度リトライしても、公開するのは採用した1回分だけです。
例えば2回目のリトライを採用しても、1枚の答案なら公開用に
`20260828-001r-1.jpg` とリネームします。ローカルの試行履歴は公開ファイル名に含めません。

旧形式（今後は使用不可）:

```text
20260828-001-f.jpg
20260828-001-r.jpg
20260828-001-1-r.jpg
```

ページ番号のない `20260828-001f.jpg`、種別が異なる `20260828-001x-1.jpg`、
ページ番号が0の `20260828-001r-0.jpg` も無効です。

## ビルドとチェック

```sh
npm ci
npm test
npm run build
```

ビルド時に命名形式、保存先との日付・学習セット番号の一致、各答案の `-1` の存在を確認します。
不正な画像があれば、対象パスと理由を示して停止します。
従来の入力場所 `public/images/` に残っている画像にも新しい命名形式を適用します。
QUESTION画像はこのLOG命名チェックの対象外です。

既存の旧名画像は新形式にリネームし、画像を直接参照している箇所があれば更新してからビルドしてください。
生成物は `public/records/YYYYMMDD/NNN/` に出力されます。
ビルドは出力先の旧名画像を自動削除しないため、既存の生成画像も新名へ移行してください。
今回の変更ではLOG・SESSIONの表示方法、PCのカラム構成、`session.md` の構造は変更しません。
