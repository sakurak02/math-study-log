# Math Study Log

## 公開LOG画像の命名ルール

保存先は `content/records/YYYYMMDD/NNN/images/` です。

```text
YYYYMMDD-NNNf-M.jpg
YYYYMMDD-NNNr-M.jpg
```

- `YYYYMMDD`: 学習日。`records/` 直下の日付フォルダと一致させます。
- `NNN`: その日の学習セット番号（`001`, `002`, `003`, …）。親フォルダと一致させます。
- `f`: first（最初の答案）。`r`: retry（公開に採用した1回分の再挑戦答案）。
- `M`: その答案の画像ページ番号。1から始まる整数で、先頭に0を付けません。画像が1枚でも必ず `-1` を付けます。
- 種別と拡張子は小文字の `f` / `r` と `.jpg` を使用します。

例（同一セット内ではfirst→retry、同じ種別ではページ番号の数値順に掲載）:

```text
content/records/20260828/001/images/
  20260828-001f-1.jpg
  20260828-001f-2.jpg
  20260828-001r-1.jpg
  20260828-001r-2.jpg
```

末尾の `-1`, `-2`, `-3` は**リトライ回数ではありません**。
ローカルで何度リトライしても、公開するのは採用した1回分だけです。
例えば2回目のリトライを採用しても、1枚の答案なら公開用に
`20260828-001r-1.jpg` とリネームします。ローカルの試行履歴は公開ファイル名に含めません。

旧形式（今後は使用不可）:

```text
20260828-001-f.jpg
20260828-001-r.jpg
20260828-001-1-r.jpg
```

ページ番号のない `20260828-001f.jpg`、種別が異なる `20260828-001x-1.jpg`、
ページ番号が0の `20260828-001r-0.jpg` も無効です。

## ビルドとチェック

```sh
npm ci
npm test
npm run build
```

ビルド時に命名形式、保存先との日付・学習セット番号の一致、各答案の `-1` の存在を確認します。
不正な画像があれば、対象パスと理由を示して停止します。
従来の入力場所 `public/images/` に残っている画像にも新しい命名形式を適用します。
QUESTION画像はこのLOG命名チェックの対象外です。

既存の旧名画像は新形式にリネームし、画像を直接参照している箇所があれば更新してからビルドしてください。
生成物は `public/records/YYYYMMDD/NNN/` に出力されます。
ビルドは出力先の旧名画像を自動削除しないため、既存の生成画像も新名へ移行してください。

## 学習セットの統合ページとSESSION

各セットは `records/YYYYMMDD/NNN/index.html` にLOGとSESSIONをまとめて表示します。
日付ページの各セットの `OPEN` から開けます。同じ日の `001`・`002`・`003` はそれぞれ別ページです。
トップページの構造は変更せず、LOG一覧・SESSION一覧のリンク先も統合ページにしています。
以前の `log.html` / `session.html` は統合ページへ自動移動します（手動リンクもあります）。

新規記事には、小文字の次のファイル名を使用してください。

```text
content/records/20260828/001/
  images/
    20260828-001f-1.jpg
    20260828-001r-1.jpg
    20260828-001r-2.jpg
  session-f.md
  session-r.md
```

- FIRST段: `f`画像と `session-f.md`。
- RETRY段: `r`画像と `session-r.md`。複数画像は既存のページ番号の数値順です。
- 各Markdownは従来と同じ数式・`details`・`summary`の記法が使えます。
- 一方の画像やSESSIONがまだない場合は、その側に未登録の案内を表示します。
- タイトルは既存の `meta.json` があればそれを優先し、なければ `session.md`、`session-f.md`、`session-r.md` の順に選び、従来どおりfront matterの `title`、H1見出し、日付・番号の順で決定します。

### 表示

幅が900pxを超える画面では、各段を左LOG・右SESSIONの約50:50で表示します。
2列は固定で回り込まず、段の高さは内容の長い側に合わせます。カラム単位の独立スクロールはありません。
長い数式・表・コードの横スクロールは従来どおり内容単位で使用できます。
900px以下ではFIRSTのLOG→SESSION、続いてRETRYのLOG→SESSIONの縦並びです。タブ切替はありません。
答案画像はクリック・キーボード操作で拡大でき、閉じるボタンまたはEscapeで戻れます。

### 既存記事との互換性

`session.md` だけの既存セットは、そのまま利用できます。本文や見出しを推測で分割しません。
PCでは左にFIRST・RETRYのLOG、右に全文を一度だけ「共通SESSION」として表示します。
スマホではFIRST・RETRYのLOGの後に共通SESSIONを全文表示します。

段階別ファイルと `session.md` が共存する場合、FIRST・RETRYの対応表示の後に共通SESSIONを全文掲載します。
段階別のSESSIONが不足しても旧本文を勝手に割り当てません。段階別ファイルへの移行は任意です。
既存画像名・画像のビルドチェック・数学記事本文を変更する必要はありません。
